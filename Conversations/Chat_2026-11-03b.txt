### Implement Haptic Feedback for Quest Controllers
As mentioned earlier, adding tactile vibration makes physical actions (rolling, clicking menu items, changing appearance settings) feel much more responsive in WebXR. You can add a lightweight haptic helper and plug it into your controller events:

JavaScript

```
function triggerHaptic(intensity = 0.5, duration = 50) {
  const session = renderer.xr.getSession();
  if (!session) return;
  for (const source of session.inputSources) {
    if (source.gamepad && source.gamepad.hapticActuators && source.gamepad.hapticActuators.length > 0) {
      source.gamepad.hapticActuators[0].pulse(intensity, duration);
    }
  }
}
```

- **Where to call it:**

- Inside `finishRoll()` when a match is made (e.g., `triggerHaptic(0.8, 100)`).
- Inside `activateMenuItem()` when pressing a menu button.
- Inside `applyAppearanceDrag` or slider interaction changes for subtle feedback.

# Splitting `app/main.js` into ES Modules

`main.js` is about 1,600 lines. This guide splits it in small, verifiable steps and keeps the current constraints:

- No build step.
- The Three.js r160 CDN import map in `index.html` stays unchanged.
- All files stay under `app/`, and URLs stay relative to `index.html`.

## 1. Ground rules
- Native `<script type="module" src="main.js">` and relative imports with the explicit `.js` extension (`import { COLORS } from './constants.js'`).
- The import map already resolves `three`, so every module can `import * as THREE from 'three'`.
- Move code in one module at a time. After each move, run `node --check` on the touched files, load the page, roll the cube, and test one MR action.
- Keep `BUILD_TIMESTAMP` in `constants.js`, and keep updating it on every change.
- Avoid circular imports. Dependencies flow downward: `constants` → `state` / `audio` → `scene` / `panels` → `xr` / `appearance` → `main`.

## 2. Target layout
| File | Contents (current `main.js` region) |
|---|---|
| `constants.js` | `BUILD_TIMESTAMP`, `COLORS`, `INITIAL_ORIENTATION`, board and cell sizes, `ROLL_SECONDS`, `MESSAGE_SECONDS`, colour and opacity defaults, `HOMES`, `AP_*` layout constants, `CONFETTI_*`. Pure data only, no THREE objects. |
| `audio.js` | `unlockAudio`, `playClick`, `playSwoop`. Exports a small API and owns `audioCtx`. Later home for the `THREE.AudioListener` or a mute toggle. |
| `haptics.js` (or inside `xr.js`) | `triggerHaptic`, `lastHapticAt` throttle. |
| `scene.js` | Renderer, scene, camera, `worldGroup`, sky, board, grid, `cube`, plus `cellToLocal`. Exports the objects other modules need. |
| `icons.js` | `drawIcon`, `makeIconTexture`, `redrawIconTexture`, `iconTextures`, `shapeStyles`, `removeIcon`, `icons` map, `buildIconsFromPattern`. |
| `panels.js` | In-world status, debug and scores panels, with `drawScoresPanel`, `updateDebug` and `updateColorTable`. |
| `game.js` | State (`level`, `orientation`, `win`, `levelScore`, timers, `sessionRecords`), `tryRoll`, `finishRoll`, `generateLevel`, `restartLevel`, `nextLevel`, scoring helpers. Calls `audio` and `haptics`, and exposes `onChange` callbacks instead of touching the DOM. |
| `hud.js` | DOM HUD (`updateHUD`, records table) and message auto-clear. |
| `celebration.js` | Confetti and panel pulse (`startCelebration`, `stopCelebration`, `updateCelebration`). |
| `xr.js` | `sessionstart` / `sessionend` handlers, controllers, `readXRInput`, `updateWorldDrag`, thumbstick roll, `resetWorldForMR`, home pose. |
| `menu.js` | Controller menu: draw, hover, `activateMenuItem`. |
| `appearance.js` | Appearance model, localStorage, HSV helpers, panel drawing, drag handling, `flushAppearance`. |
| `input-desktop.js` | Keyboard handlers. |
| `main.js` | Imports, wiring, and the animation loop only. |

## 3. Migration order
Start with the least-coupled code. Each step is a separate commit-sized change.
1. **`constants.js`.** Move pure values. `main.js` imports them. Run `node --check` on both.
2. **`audio.js`.** Self-contained. Export `unlockAudio`, `playClick`, `playSwoop`.
3. **`haptics.js`.** Needs only `renderer`. Pass the renderer in (`initHaptics(renderer)`) rather than importing a global.
4. **`icons.js`**, then **`celebration.js`**. Both depend on `worldGroup` and `COLORS`. Export an `init…(worldGroup, panel)` function.
5. **`scene.js`.** Highest-impact move. Export `renderer`, `scene`, `camera`, `worldGroup`, `cube`, `boardPlane` and so on, so later modules import them instead of closing over module-level variables.
6. **`panels.js`** and **`hud.js`.**
7. **`game.js`.** Split state from side effects: game logic emits events, and `hud` / `panels` / `celebration` subscribe. This removes most cross-module calls (`updateHUD()` from inside `finishRoll`).
8. **`xr.js`**, **`menu.js`**, **`appearance.js`.** Pass shared state such as `appearanceOpen` and `menuOpen` through a small exported state object, not bare `let` exports. Imported bindings are read-only from the importing side.
9. **`input-desktop.js`.** Reduce `main.js` to wiring plus the loop.

## 4. Pitfalls to watch for
- **Mutable shared `let`s.** An imported `let` can't be reassigned by importers. Use an object (`state.win = true`) or setter functions. Candidates: `win`, `message`, `roll`, `orientation`, `levelScore`, `appearanceOpen`, `menuOpen`, `cubeColorDirty`.
- **Load order and side effects.** Today module-level code runs top to bottom (for example `generateLevel()` before the loop, and `cubeColorDirty = true` before the initial flush). Move these into explicit `init()` calls from `main.js`.
- **Audio unlock.** Keep the `keydown` / `pointerdown` listeners and the `sessionstart` call to `unlockAudio()`.
- **Per-frame order.** Keep the loop order exactly as it is: timer HUD, message clear, debug, roll, exit-pending return, then input and UI.
- **Caching during dev.** The local server serves the files unbundled, so hard-refresh (or add `?v=`) after edits. On Quest, clear the cache or bump the query string.
- **Performance.** More files means more requests. This is negligible on a local server. If it ever matters, `modulepreload` links in `index.html` fix it without a build step.

## 5. Optional later features this enables
- Custom level loader: `levels.js`, with `generateLevel` taking a level source.
- Saved player profiles: `profile.js` wrapping localStorage (scores, appearance, mute).
- Positional audio via `THREE.AudioListener` inside `audio.js` only.

## 6. Verification checklist (after each step)
- [ ] `node --check` passes on every changed file.
- [ ] Desktop: loads with no console errors, keyboard roll works, level completes, N advances.
- [ ] Desktop: scores panel and HUD table update.
- [ ] Quest: enter MR (game resets), roll, grips drag the world, menu and appearance panel work.
- [ ] Sounds, haptics and the celebration still fire.
- [ ] `BUILD_TIMESTAMP` shows the new value in the debug panel.
- [ ] Any new files are staged. Changes to existing files are left unstaged for diff review.
